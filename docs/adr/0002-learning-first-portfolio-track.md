# ADR-002: Learning-first portfolio track

- **Status:** Accepted
- **Date:** 2026-11-02
- **Related:** docs/learning/CURRICULUM.md; was ADR-035

## Context
- A 2026 competitor scan found that free, often AI-assisted programs already ship every headline
  feature of the planned product. Commercial success looked unlikely.
- Up to then the work optimized for velocity, and an AI assistant wrote the DSP. The owner
  understood the system's design but hadn't built its core, which is where the value to a
  portfolio lies.
- The owner has a solid signals-and-systems background and wants to understand as many DSP
  techniques and radio protocols as possible, and to show that understanding publicly.

## Decision
1. **The product is the owner's understanding,** shown in devlog write-ups (`site/`). The software
   is the lab bench: it records, replays, and visualizes, and each module's code plugs into it.
   Feature velocity is not a goal.
2. **The work is organized as curriculum modules** (docs/learning/CURRICULUM.md). Protocols are
   chosen for the new concept each one teaches, not to grow a mode count.
3. **The owner writes the module code:** the Python prototype, the golden vectors, and the C++
   port. Claude tutors and reviews, and writes module DSP or decoder code only when the owner asks
   for a specific piece (marked in the post's AI-use note). Claude handles plumbing: UI, build,
   CI, protocol, file I/O, and plot helpers.
4. **Product work is parked:** licensing tiers, payments, a hosted remote service, the AI
   assistant, transmit and CAT, multi-client remote, signed installers.
5. **Rules kept:** clean-room (ADR-004), real-time safety in C++, golden vectors and fuzz tests,
   provenance notes, units in names, and the code style. They're good engineering, and they make
   the write-ups defensible.
6. **Open source:** code under MIT (ADR-005 keeps GPL code out of the process); devlog text
   under CC BY 4.0. The site is static (Astro) on Cloudflare Pages, with figures generated by
   scripts in the repo.
7. **Only lawful captures:** amateur, broadcast, aviation (ADS-B), maritime (AIS), weather
   satellites, ISM sensors. No pagers, cellular, cordless, encrypted, or trunked public-safety
   voice. Posts publish only content that's lawful to divulge.

## Consequences
- Easier: no market pressure, and every module ends with a deliverable (a post, code, and
  measurements).
- Harder: slow feature progress, and the app stays a bench rather than a polished product.
  Structure has to replace deadlines (the module loop and a cadence target), or the project drifts.
- Revisit triggers: posts draw real readership or job interest (lean in); the owner stops enjoying
  the module loop (change the format, not necessarily the goal); a product idea with a real moat
  appears.
